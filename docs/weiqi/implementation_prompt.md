# 实现提示词：《围棋 3D》单文件 Web 游戏

> 用途：把本文件整体作为提示词交给 AI 编码助手，即可在与《中国象棋 3D》《荣光宝石商》**同一工程标准**下产出新的单文件游戏。
> 参照物：
> - `games/chinese_chess.html`（762 KB，three.js r149 UMD 内联，**真 3D 首选参照**：透视相机 + 光照 + 阴影 + PBR + 程序化几何）
> - `games/glory_&_gems.html`（1.5 MB，**交互 / UI / 存档 / AI 调度风格参照**）
> 交付物：`games/weiqi.html` + `docs/weiqi/conceptual design.md`（可选追加 `docs/weiqi/res/` 存放 Blender 资产）。

---

## 0. 角色与任务

你是一名资深 Web 3D 游戏工程师。请在一个**单文件 HTML**中实现完整可玩、可离线运行的 3D 围棋游戏，支持 **1~2 人单设备游玩**，内置**多档人机 AI**，棋子 / 棋盘 / 场景全部为 **Three.js 实时 3D 渲染**，界面为简体中文、移动端触屏优先。

美术资产允许用 **Blender 建模**（见第 4.5 节），但最终必须内联进同一个 HTML 文件，运行时不得加载任何外部模型文件。

## 2. 硬性约束（不可违反）

1. **唯一运行时交付物是一个 HTML 文件**，双击可运行，断网可用。
2. **不允许任何外部资源**：不得出现 `<img src>`、`<audio>`、`@import`、CDN `<script src>`、`fetch()`、外部 Worker 文件、`.glb`/`.gltf`/`.obj` 外链、`base64,` 大段数据。
3. Three.js 必须**内联为压缩源码**（r149 UMD 或更高 UMD），禁止 `type="module"` / `import` / `importmap`。
4. 除 Three.js 外**不引入任何第三方库**：AI、气判定、数子、坐标记谱、手柄导航、缓动、音效、存档全部手写。
5. 所有贴图用 Canvas 2D 现画；所有音效用 WebAudio 振荡器 / 噪声合成；3D 模型用程序化几何，或 Blender 导出后**内联精简顶点 JSON**（第 4.5 节）。
6. 界面文案简体中文；所有可点元素在触屏上**最小命中尺寸 ≥ 44 px**（逻辑像素）。
7. `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))` —— DPR 上限 2。
8. 文件总体积目标 **< 900 KB**（three.js 内联约占 600 KB，留给自写代码与资产 < 300 KB）。
9. 无构建步骤：不得要求 npm / 打包器 / 本地服务器。
10. 写入 DOM 的任何用户数据（玩家名、存档、棋谱）必须 `escHtml` 转义；颜色值走 6 位 hex 白名单校验（参照 `chinese_chess.html:1181` / `:1186`）。
11. 通过项目校验脚本：`node dev/check_single_file.js games/weiqi.html`（该脚本会检查语法、外链负面清单、`console.log` / `TODO` 残留、体积）。

## 3. 游戏规则规范（围棋，必须精确实现）

> 规则精度是本作的**第一优先级**。气、提子、禁入点、劫争、数子的实现必须可被 Node 单元测试逐条断言（第 10、12 节）。

### 3.1 棋盘与棋子

- 支持三种盘面尺寸，可在开局设置中切换：**19 路（默认）/ 13 路 / 9 路**（N 路 = N×N 个交叉点；19 路 = 361 点）。
- 19 路星位 9 个（含天元），13 路与 9 路各 5 个（四角 + 天元），按标准坐标绘制小黑点。
- 坐标记法：横轴字母 `A`~`T`（**跳过 `I`**），纵轴数字 `1`~`19`（自下而上）；如 `Q16`、`D4`。
- 黑先白后；棋子为**双凸透镜形**（蛤贝白子 / 那智黑石），直径 ≈ 0.98 格、厚 ≈ 0.38 格（真实比例：格距 22 mm，子径 21.5 mm，厚 8~9 mm）。

### 3.2 落子、气与提子（逐条实现，必须可测试）

| 规则 | 要点 |
|---|---|
| 落子 | 只能落在**空交叉点**；已有子的点不可落 |
| 连通块 | 同色**上下左右**相邻（**不含对角**）连成一块 |
| 气 | 连通块紧邻的空交叉点数量；棋盘边界外的空间不算气 |
| 提子 | 落子后，先检查相邻的**对方**块：气为 0 则整块提掉；被提的子计入己方提子数 |
| 禁入点（自杀） | 落子后己方块气为 0 **且没有提到任何子** → 该点为禁着点，禁止落子 |
| 打劫（ko） | **禁止全局同形再现**：用 Zobrist 哈希维护局面历史集合，落子后若局面与历史任一局面相同 → 非法（`superko`，默认开启） |
| 简化劫 | AI 内部模拟（playout）可用**简单劫**（仅禁止立即回提单子劫）以省性能，但主对局判定必须用 superko |
| 停一手（pass） | 允许；双方连续 pass → 进入数子阶段 |
| 循环 | 若规则设置为关闭 superko，则同一局面出现 3 次 → 判**无胜负（和棋）** |

### 3.3 终局、数子与胜负

采用**中国规则（数子法）**为主：

1. 双方连续停一手（或任一方认输、或达到局面重复上限）→ 进入**数子阶段**。
2. 数子阶段交互：
   - 系统（或 AI）**自动提议死子**（用第 7 节的盘面评估给出死子集合），棋盘上以半透明淡化 + 叉号标记；
   - 双方玩家可**点击棋盘上的子切换死活**（点一次标记死、再点取消），点击会实时更新目数预览；
   - 显示实时明细表：`黑：子 X + 地 Y = Z 目` / `白：子 X + 地 Y + 贴目 K = Z' 目`；
   - **双人模式需双方各点一次「确认」**（两个按钮：`黑方确认` / `白方确认`）；**人机模式只需玩家确认**（AI 用自身评估自动同意，若评估与玩家标记差距过大可拒绝并提示继续对弈）；
   - 「继续对弈」按钮可取消数子，回到对局。
3. 结算公式（中国数子法）：
   - 死子全部移出棋盘后，`某方子数 = 该方盘上子数 + 该方围住的空点`；
   - 空点归属：该空点连通区域**只与一方棋子相邻** → 归该方；**同时与双方相邻（公气 / 双活）** → 中立，双方都不计；
   - 黑方总子数 > `(N²+1)/2 + 贴目/2` → 黑胜，差值为胜出子数（换算为「目」展示时用 `子数差`，并在结算中标明「中国规则·数子」）。
4. 其他终局：
   - **认输** → 立即判负，进入结算；
   - **超时**（若开启计时）→ 判负；
   - 无胜负（三次重复且未开启 superko）→ 平局。
5. 贴目（Komi）与让子：
   - 19 路默认 **贴目 7.5**（可改 6.5 / 5.5 / 0.5 / 自定义 0.5 步进）；
   - 13 路 / 9 路默认 6.5；
   - **让子 0~9 子**（标准让子点组合，黑方预置，白方随后落子；让子时贴目默认 0.5）；
   - 让子数、贴目必须同时作用于**数子结算与 AI 评估**。
6. 结算展示：胜方（黑 / 白 / 和）、胜出目数 / 子数、终局原因（数子 / 认输 / 无胜负）、总手数、双方提子数、耗时、最大提子数。

### 3.4 记谱与回放

- 内部结构：`moves: [{ n:1, c:'black'|'white', x, y, pass?:true, captured:[[x,y],...], hash }]`。
- 展示格式：`1. 黑 Q16`、`2. 白 D4`、`黑 停一手`；点列表项可跳转到该手。
- 回放：前进 / 后退 / 回到开局 / 跳到末手，棋盘与提子数同步重建。
- **不要求** SGF 导入导出（零外部文件约束下可选，若实现则只用文本框粘贴 / 复制）。

### 3.5 对局模式

| 模式 | 说明 |
|---|---|
| 单人（人机） | 玩家可执黑或执白；另一方由 AI 控制；支持让子与贴目配置 |
| 双人（同设备） | 双方轮流操作同一设备，黑先；默认棋盘正放，可开「视角跟随当前落子方」（棋盘旋转 180° 平滑过渡） |

- 人机模式下棋盘默认正对玩家（执黑正立，执白则整体旋转 180°，使棋子与星位朝向自己）。
- 双人模式使用项目**上下坐席**惯例：黑方坐下方、白方坐上方（上方一侧 UI 文字倒置）。

## 4. 3D 美术与场景规范

### 4.1 渲染与相机

- `WebGLRenderer({ antialias:true, powerPreference:'high-performance' })`，`shadowMap.enabled = true`，`type = PCFSoftShadowMap`，`outputColorSpace = SRGBColorSpace`。
- `PerspectiveCamera(45, w/h, 0.1, 200)`，**斜俯视**机位（俯角 40°~55°，水平偏转 15°~30°），棋盘居中。
- `fitCamera()`：按视口宽高比自动调整机位距离与 FOV，保证 **19 路棋盘四角**在竖屏 / 横屏 / 桌面 / 超宽屏下均完整可见并留出安全边距（竖屏把棋盘竖放占满高度）。
- 相机手势：单指拖动水平旋转（**限位 ±35°**）、双指捏合缩放（**0.6×~2.4×**，缩放锚点为棋盘中心）、双击复位；桌面端提供鼠标滚轮缩放。
- 可选复用 `chinese_chess.html:3185` 的画质层（自建 MSAA + SSAO + Bloom + 暗角），但必须能一键降级为「画质：低 / 中 / 高」，低端机默认关闭 SSAO 与 Bloom。

### 4.2 光照

- `HemisphereLight`（天空暖白 `#fff4e2` / 地面榻榻米褐 `#6b5a42`）+ 主 `DirectionalLight`（斜上方，投软阴影，`shadow.mapSize` 1024 低端 / 2048 桌面，`shadow.camera` 紧贴棋盘范围）。
- 一盏暖色 `PointLight` 模拟**纸灯**（强度低，仅作氛围，不投影或投低分辨率阴影）。
- 阴影只对「棋子 → 棋盘」与「棋盘 → 地面」开放，其余物件 `castShadow` 关闭以省性能。

### 4.3 材质与程序化贴图（全部 Canvas 绘制）

| 物件 | 规范 |
|---|---|
| 棋盘面 | Canvas 绘制**榧木 / 榉木木纹**（多道不等宽深浅条纹 + 细噪点 + 轻微年轮弧）+ 黑色细格线（线宽 ≈ 0.045 格）+ 星位小圆点 + 可选坐标标注（`A~T` / `1~19`）；`MeshStandardMaterial`，`roughness ≈ 0.5`，`metalness = 0` |
| 棋墩（棋盘体） | 厚木墩：`ExtrudeGeometry` 或 `BoxGeometry` + 边缘倒角，厚 1.8~2.4 格，底部收窄约 15%，四侧用同色木纹贴图；顶面接收棋子阴影 |
| 棋子 | **`LatheGeometry` 车削**双凸透镜剖面（顶弧 + 薄边 + 底弧），黑白共用同一剖面与几何，仅材质不同：白子 `MeshPhysicalMaterial`（`roughness 0.12`、`clearcoat 1.0`、微透感、色 `#f2ece1`），黑子 `MeshStandardMaterial`（`roughness 0.22`、色 `#171514`）；**禁止**用纯黑 `#000` 与纯白 `#fff` |
| 棋子贴图 | 无需文字，但可叠加极淡的**天然纹理**（白子微贝纹 / 黑子微石纹，Canvas 噪声 + 低对比），一张贴图黑白各一份即可 |
| 棋笥（棋盒） | 两个木盒（圆柱 + 盖，`LatheGeometry` 或 `CylinderGeometry`），直径 ≈ 1.8 格、高 ≈ 1.2 格，放于棋盘侧后方；盒内可放 5~8 枚静态棋子做装饰 |
| 和室场景 | 榻榻米地面（Canvas 草席编织纹 + 深色布边，`repeat` 平铺）、障子格窗墙面（浅色木格 + 透光纸面，可用自发光平面模拟背光）、可选坐垫；背景暗角渐变；**禁止外部 HDR / 环境贴图** |
| 单位尺度 | 以「**一格 = 1 单位**」为基准；19 路棋盘线阵 = 18 格跨距，含外沿留白 1.0 格 → 盘面宽 ≈ 21 格 |

### 4.4 棋子渲染与性能策略（本作核心工程点）

19 路最多 361 枚棋子，必须显式设计渲染方案：

1. **主渲染用 `InstancedMesh`**：黑白各一个实例化网格（`count` 动态，`instanceMatrix` 更新），共享低多边形棋子几何（≤ 320 三角形）。
2. **动画子单独 Mesh**：最新落下的一枚棋子用独立 `Mesh`（共享几何 / 材质）做下落动画，动画结束后写入实例矩阵并移除动画 Mesh（避免每帧重建整块实例矩阵）。
3. **阴影**：实例化网格开启 `castShadow`，几何面数低 + 阴影贴图 1024~2048，实测帧率后再决定是否降级为「仅最近 N 手投影」。
4. **贴盘间隙**：棋子底面与棋盘面留 0.01~0.02 单位间隙防 z-fighting；棋子不 `receiveShadow`（自阴影视觉收益低、成本高）。
5. **提子回收**：被提子从实例中移除（可用「末尾交换 + count--」技巧避免重建全部矩阵）。
6. **纹理与几何复用**：`TEX` Map 缓存（key 带尺寸）；共享几何 / 材质标记 `userData.shared = true`，`disposeGroup` 跳过共享项（参照 `chinese_chess.html` 的释放约定）；场景重建时 `TEX.clear()`。
7. 同屏 mesh 数（不含实例化子）控制在 **80 以内**；目标桌面 60 fps、中低端手机 ≥ 30 fps。

### 4.5 Blender 建模路径（允许，但必须先走程序化方案）

按「**优先 A，必要时 B**」决策：

**A. 程序化几何（推荐默认）**
用 `LatheGeometry` / `ExtrudeGeometry` / `CylinderGeometry` / `TorusGeometry` / `PlaneGeometry` 在代码里直接构建棋子、棋墩、棋笥、榻榻米、障子墙、坐垫。完全符合零依赖与体积约束，且参数可调、便于按画质档降级。
**Blender 在此方案中的用途**：造型参考、比例校验、出渲染图（用于 `docs/weiqi/res/` 与首页卡片预览图的**参考**，不得作为运行时贴图外链）。

**B. Blender 建模 + 精简顶点数据内联（仅在确有美术需求时）**

- 流程：Blender 建模 → `tools/blender_export.py` 导出 → 转成**纯 JSON 顶点 / 法线 / UV / 索引 / 材质名数组** → 内联进 `<script type="application/json" id="mesh-xxx">` → 手写 `BufferGeometry` 装配。
- **禁止**内联 base64 的 `.glb` / `.gltf` / `.obj`（体积与解析器成本不可接受）。
- 建模规范（Blender 侧）：
  - 单位 1 Blender 单位 = **1 格**；19 路棋盘盘面宽 ≈ 21 单位；棋子直径 0.98、厚 0.38；
  - 变换全部应用（`Ctrl+A` → All Transforms），原点置于物体**底面中心**，Y 轴向上统一（导出时转 Three.js 的 Y-up）；
  - 三角化（`Triangulate`）、合并重复顶点、**硬边法线**；不加厚修改器之外的未应用修改器；
  - 面数预算：单件 ≤ 3 000 三角形，全套 ≤ 2 万三角形；
  - 材质只保留名字（`stone_black` / `stone_white` / `wood_board` / `wood_bowl` / `tatami` / `shoji`），运行时由 Three.js 重新赋材质。
- 导出脚本规格（`tools/blender_export.py`，随仓库提交）：
  - 命令：`blender --background --python tools/blender_export.py -- --in docs/weiqi/res/xxx.blend --out docs/weiqi/res/mesh.json`；
  - 只导出**选中**物体或指定集合；顶点坐标**量化到 4 位小数**并去掉 `0.0` 冗余、法线 3 位小数、索引用最小整数类型可省 30%~50% 体积；
  - 输出 `{ "meshes":[ { "name", "material", "positions":[...], "normals":[...], "uvs":[...], "indices":[...] } ] }`。
- 体积红线：内联 JSON **≤ 150 KB**、总顶点数 **≤ 3 万**；若内联后总文件 > 900 KB，**必须回退方案 A**。
- 必须同时提交 `.blend` 源文件与导出脚本到 `docs/weiqi/res/`（开发资产，不参与运行时），并在 `conceptual design.md` 的技术架构中记录导出命令、顶点数与面数。
- 装配后的模型必须仍满足：可被 `addClickable` 命中（用不可见包围体做拾取代理，禁止直接对高模射线求交）。

### 4.6 视觉反馈（必须实现的 7 种）

1. **幽灵子预览**：悬停（桌面）或选中点（触屏）时，在目标交叉点显示半透明棋子（`opacity 0.45`）+ 实地/虚地的合法/非法色提示（合法墨绿，非法朱红）。
2. **最后一手标记**：最近一手棋子上叠加朱红小圆环（`#b23a2e`，可开关），随落子移动到新位置。
3. **上一步 / 历史标记**：可选显示手数（扁平数字片贴在子面上，Canvas 贴图），用于复盘。
4. **提子动画**：被提子整体淡出 + 轻微上浮旋转（≈ 300 ms），同时飞向对应棋笥方向并缩小；`Busy` 屏蔽输入。
5. **落子动画**：棋子自上方 0.8~1.2 单位落入 + `easeOutCubic` + 落定轻微回弹（总时长 220~320 ms）。
6. **打劫提示**：出现劫争时在被提点显示脉冲红圈 + 顶部提示「打劫：此点暂不可落（全局同形）」。
7. **形势判断（可选开关）**：估算双方地盘，用半透明色块覆盖双方势力范围并在顶部显示 `黑约 X 目 / 白约 Y 目`（AI 评估结果复用；必须标注「估算」）。

## 5. 交互规范

### 5.1 拾取（19 路小格距是难点）

- 优先用 `THREE.Raycaster` 命中**棋子 InstancedMesh**（读取 `intersection.instanceId` 判断该点归属）。
- **交叉点回退拾取**：射线与棋盘平面求交后换算为最近交叉点（`gridFromWorld`），命中容差按视口动态计算 —— 只要点击落在目标交叉点的 **±0.45 格** 内即视为该点，避免小屏点不准。
- 触屏设备：初始缩放保证**相邻交叉点屏幕间距 ≥ 22 px**；若视口不足则自动降低初始缩放并提示可双指放大。
- 非法的空点 / 已有子的点 / 禁着点必须给出**具体原因**（「该点已有棋子」「禁着点：落子后无气」「打劫：全局同形禁着」）。
- 坐标换算函数集中定义：`worldFromGrid(x,y)` / `gridFromWorld(wx,wz)` / `intersectionIndex(x,y)`，禁止散落魔法数字。

### 5.2 操作流程

1. 点击空交叉点 → 幽灵子预览（触屏确认式：首次点击预览、再次点击同一交点落子；或提供「落子确认」开关，默认**直接落子**在桌面、**二次确认**在触屏小盘面）。
2. 落子成功 → 落子动画 + 音效 + 提子动画 + 更新提子数 / 手数 / 棋谱。
3. 非法操作 → 抖动 + `err` 音效 + toast 提示原因。
4. 长按棋盘（或双指长按）→ 弹出「标记」菜单（可选功能：三角 / 方块 / 字母标记，仅用于复盘，不参与规则）。

### 5.3 对局操作栏

- 按钮：`悔棋`、`停一手`、`认输`、`形势判断`、`显示手数`、`数子`、`重开`、`返回首页`。
- 悔棋规则：双人模式退 1 手；人机模式退 2 手（回到玩家回合）；悔棋必须**还原提子数与局面哈希历史**（不能只回退棋盘数组）。
- `数子` 按钮：手动提前进入数子阶段（双方同意后生效）。
- 除暂停类操作外均需二次确认弹窗，参照 `chinese_chess.html` 的 `PauseModal` / 确认弹窗写法。

### 5.4 动画与输入屏蔽

- 全局 `Busy` 计数 + `AI.running`：落子 / 提子 / 相机过渡 / AI 思考 / 数子结算动画期间屏蔽拾取分发。
- 复用「单一入口分发」模式：`dispatchTap(...)` 按当前屏幕与阶段（对局 / 数子 / 回放）路由；**手柄键盘导航与触摸共用同一入口**。

## 7. AI 规范

### 7.1 现实目标（不要过度承诺）

单文件 JS 无法做出强围棋 AI。**明确目标**：

- 9 路：中坚档应能稳定击败初学者，大师档具备基本死活与联络意识；
- 13 路：娱乐陪练水平，能完成整局、不犯「自填眼」「送吃大块」之类低级错误；
- 19 路：以陪练与体验为主（局部战斗与吃子有反应，全局战略较弱），文档与 UI 中**如实标注**强度区间。

### 7.2 难度分档

沿用项目 4 档命名与色标（`AI_LEVELS` 结构：`{name, desc, cls, hex}`）：

| 档位 | 策略 |
|---|---|
| 1 简单 | 随机合法点 + 基础过滤（不填自己的眼、不无谓送吃、优先靠近已有棋子的点）；可随机放弃局部 |
| 2 普通 | 启发式评估 1 层前瞻：吃子 / 逃气 / 连接 / 断开 / 侵消；拒绝自填眼 |
| 3 困难 | **轻量 MCTS**：UCB1（C ≈ 1.0）+ 启发式 playout + 时间预算 300~600 ms + 节点上限（2 万 ~ 5 万） |
| 4 大师 | **MCTS + 增强**：候选点裁剪（邻域 2 格内 + 大场 / 星位 + 开局书）、playout 加「提子后立即应对」策略、终局数子估值、时间预算 800~1500 ms + 根节点 RAVE（可选） |

### 7.3 搜索与评估（必须手写，禁止用库）

- **候选着法**：所有空点中排除禁入点 / 打劫禁着 / **自填真眼点**；再按启发排序（邻接已有子距离 ≤2 优先、吃子 / 打劫 / 逃气 / 断点优先、星位与大场按盘面尺寸给出权重）。
- **眼位检测（绝对必须）**：3×3 模式判断真眼（中心空 + 四正交为同色 + 对角绝大多数为同色，考虑边角简化）；AI 在任何阶段都**不得落子填自己的真眼**，且当「已无有意义的着法」时必须**自动停一手**，否则对局永远无法结束。
- **Playout 策略**：以概率 `0.7` 选择「邻近已有棋子的空点」并叠加吃子 / 逃气偏好，`0.3` 随机；单次 playout 手数上限 `N² × 1.5` 后按当前盘面数子结束；playout 内部只做**简单劫**判定。
- **终局估值**：`面积法数子（子 + 地） − 贴目` 作为胜负判定，MCTS 回传胜率。
- **让子 / 贴目对接**：让子与贴目必须进入评估（例如 AI 执白让 2 子时按补偿策略主动挑起战斗）；AI 的优势/劣势判断随贴目变化。
- **认输**：MCTS 胜率 < 8% 且手数 > `N²×0.35` → 自动认输（仅 3、4 档）；简单 / 普通档不认输。
- **开局书**：19 路给出 3~5 组常见开局应对（星 / 小目简单定式），9 路 / 13 路给出 5~10 个偏好点（含角部 3-3、3-4、天元）；开局书用数据表实现，只在前若干手生效。
- 每档在评分持平时加入微随机，避免每局完全相同的棋路。

### 7.4 异步与体验

- AI 思考**必须非阻塞**：MCTS 按「每次同步推进 ≤ 100 ms 后 `await` / `setTimeout(0)` 让帧」的分片方式执行（可选在支持的浏览器上用内联 `Blob` Worker 加速，但**不得**依赖外部 Worker 文件，且 Worker 不可用时自动回退分片模式）。
- 思考期间：显示「AI 思考中…」+ 顶部信息条轻微脉冲 + 可选显示已模拟局数；`AI.running` 防重入；暂停或切屏时放弃本次思考。
- 落子延时：`260 + lv*220 + (600~2200 随机)` ms，避免瞬间落子造成突兀；**AI 思考时间不得叠加在延时之上导致超时感**（思考与延时并行计时）。
- **绝对禁止**：单次同步阻塞 > 120 ms（低端机掉帧），参照物在 MCTS 上出现过同步阻塞问题，务必避免。

## 8. 数据与持久化

- localStorage key 命名沿用项目风格（`cc_` = 象棋，本作 `wq_` = 围棋）：
  - `wq_save_v1` —— 当前对局（最多 1 份）

- 存档结构（实现时按此定义并做版本字段）：
  ```js

    aiLevel:3, humanColor:'black'|'white',
    board:[/* N²，0 空 / 1 黑 / 2 白 */],
    turn:'black'|'white', captures:{ black:0, white:0 },
  ```

- 每局结束写入 `wq_records_v1`（0 手无效局不记），超过 50 条丢弃最旧。

## 9. 性能与移动端适配

- DPR ≤ 2；`resize` / `orientationchange` 防抖 200 ms 后重建布局（横竖屏切换延迟 250 ms 等待系统旋转完成）。
- 纹理使用 `TEX` Map 缓存（key 带尺寸）；场景重建 `TEX.clear()`；局部失效按前缀删除；`disposeGroup` 逐个释放 geometry / material / map（共享资源跳过）。
- 棋子几何 / 材质**全局共享**，黑白各一套；实例化网格复用，禁止 361 次新建对象。
- 阴影贴图 1024（低端）~ 2048（桌面），按 `devicePixelRatio` 与视口尺寸自动降级；画质档「低」时关闭 SSAO / Bloom 并降到 1024。
- 数子 / 形势判断的领土计算必须走**一次洪水填充**（O(N²)），不得写成逐点重复遍历。
- 目标：桌面 60 fps，中低端手机 ≥ 30 fps；AI 思考期间帧率下降不超过 30%。
- UI 使用 DOM（HTML/CSS）叠在 canvas 之上，3D 只负责棋盘、棋子与场景，禁止在 canvas 里绘制大段文字 UI。

## 11. 音效规范（WebAudio 合成，零素材）

用 `AudioContext` + `OscillatorNode` / 噪声 `BufferSource` + `BiquadFilter` 现场合成，`unlockAudio()` 必须在用户手势中调用（iOS 需补播一帧近静音 buffer）。

| key | 音色设计 |
|---|---|
| `pick` | 极轻木质点击（三角波 900 Hz，衰减 0.05 s），选中 / 预览 |
| `drop` | **落子「啪」**：噪声瞬态 + 2.5~4.5 kHz 带通脆响 + 200~400 Hz 木质共振，衰减 0.15 s；白子（蛤贝）音偏高脆、黑子（那智石）偏低厚，用同一合成器换参数实现 |
| `capture` | 落子音 + 连续 3~5 声快速叠加的轻击（模拟提子收子）+ 低频 130 Hz，总计 ≈ 0.35 s |
| `pass` | 柔和双音（单声「停一手」提示），短促但明显 |
| `ko` | 两次短促中音交替（提示打劫禁着） |
| `err` | 200 Hz 方波短促，非法操作 |
| `nav` | 1245 Hz 三角波极短音，手柄 / 按钮导航 |
| `undo` | 反向滑音（向下），悔棋 |
| `count` | 数子阶段轻快连击（每秒 6~8 次轻击），随目数展示播放，短而克制 |
| `win` / `lose` | C5-E5-G5-C6 琶音 / 下行琶音，结算 |
| `start` | 523 Hz，开局 |

支持 `volScale` 参数在密集场景（提子连击、数子）临时降音量；提供静音开关并持久化到 `wq_settings_v1`。

## 15. 禁止事项（负面清单）
