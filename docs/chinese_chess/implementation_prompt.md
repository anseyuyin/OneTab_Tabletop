# 实现提示词：《中国象棋 3D》单文件 Web 游戏

> 用途：把本文件整体作为提示词交给 AI 编码助手，即可在与《荣光宝石商》**同一工程标准**下产出新的单文件游戏。
> 参照物：`games/glory_&_gems.html`（7121 行 / 约 611 KB，three.js r149 UMD 内嵌，零外部依赖）。
> 交付物：`games/chinese_chess.html` + `docs/chinese_chess/conceptual design.md`。

---

## 0. 角色与任务

你是一名资深 Web 3D 游戏工程师。请在一个**单文件 HTML**中实现完整可玩、可离线运行的 3D 中国象棋游戏，支持 **1~2 人单设备游玩**，内置**多档人机 AI**，棋子 / 棋盘 / 场景全部为 **Three.js 实时 3D 渲染**，界面为简体中文、移动端触屏优先。

## 2. 硬性约束（不可违反）

1. **唯一交付物是一个 HTML 文件**，双击可运行，断网可用。
2. **不允许任何外部资源**：不得出现 `<img src>`、`<audio>`、`@import`、CDN `<script src>`、`fetch()`、Web Worker 外部文件、GLB/GLTF/OBJ 外链。
3. Three.js 必须**内联为压缩源码**（r149 UMD 或更高 UMD 版本），禁止 `type="module"` / `import` / `importmap`。
4. 除 Three.js 外**不引入任何第三方库**：AI 搜索、走法生成、记谱解析、手柄导航、缓动、音效、存档全部手写。
5. 所有贴图用 Canvas 2D 现画；所有音效用 WebAudio 振荡器 / 噪声合成。
6. 界面文案简体中文；所有可点元素在触屏上**最小命中尺寸 ≥ 44 px**（逻辑像素）。
7. `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`——DPR 上限 2。
8. 文件总体积目标 **< 900 KB**（three.js 内联约占 600 KB）。
9. 无构建步骤：不得要求 npm / 打包器 / 本地服务器。
10. 写入 DOM 的任何用户数据（玩家名、存档、记谱）必须 `escHtml` 转义；颜色值走 6 位 hex 白名单校验（参照 `:6089` / `:6095`）。

## 3. 游戏规则规范（中国象棋，必须精确实现）

### 3.1 棋盘与棋子

- 棋盘 **9 列（纵线）× 10 行（横线）**，中间为**河界**（第 5、6 行之间），两端各有**九宫**（3×3，含对角斜线）。
- 共 **32 枚棋子**，红黑各 16：将/帅 1、士/仕 2、象/相 2、马 2、车 2、炮 2、卒/兵 5。
- 红方先行；红方在下（第 1~3 行），黑方在上（第 8~10 行）。

### 3.2 走法规则（逐条实现，且必须可被测试）

| 棋子 | 规则要点 |
|---|---|
| 车 | 直线任意步，路径不得有子 |
| 马 | 走「日」，**蹩马腿**：前进方向相邻点有子则不可走 |
| 象 / 相 | 走「田」，**塞象眼**：田字中心有子则不可走；**不得过河** |
| 士 / 仕 | 九宫内斜走一步 |
| 将 / 帅 | 九宫内直走一步；**将帅照面**（同纵线且中间无子）为非法局面 |
| 炮 | 不吃子时同车；**吃子必须且仅隔一个子**（炮架） |
| 兵 / 卒 | 未过河只能向前一步；过河后可左右各一步，**永不后退** |

### 3.3 合法性判定

- 走子后**己方将帅不得被将军**（含送将、以及由照面导致的"暴露将军"），否则该着法非法。
- 无合法着法时：被将军 → **将死判负**；未被将军 → **困毙同样判负**（中国象棋规则，不要按国际象棋判和）。
- 将军必须提示；被将军方进入"应将"状态，只允许能解将的着法被高亮。

### 3.4 终局与和棋

- 认输、将死、困毙 → 对局结束，进入结算画面。
- **三次重复局面**判和；若某一方在重复过程中始终在将军（**长将**）→ 判该长将方负。
- **自然限着**：连续 60 回合（双方合计 120 步）无吃子 → 判和。
- 结算画面展示：胜方、终局原因（将死 / 困毙 / 认输 / 和棋原因）、着数、耗时。

### 3.5 中文记谱（用于对局记录与回放）

- 实现标准**纵线记谱法**：红方纵线从右到左记 1~9，黑方从左到右记 1~9。
- 动作词：进 / 退 / 平；同线同种子力用「前 / 后」区分。
- 记录格式示例：`炮二平五`、`马8进7`、`前车进三`。
- 对局记录弹窗需能按回合对列出双方着法，并支持逐步回放（前进 / 后退 / 重置）。

### 3.6 对局模式

| 模式 | 说明 |
|---|---|
| 单人（人机） | 玩家执红或执黑可选；另一方由 AI 控制 |
| 双人（同设备） | 双方轮流操作同一设备，红先 |

- 1 人模式下，棋盘默认正对玩家；2 人模式下，棋盘采用本项目**上下坐席**惯例：红方坐下方（正立视角）、黑方坐上方（其棋子文字与世界朝向整体旋转 180°，使对面玩家正读）。
- 双人模式需提供「**视角跟随当前走子方**」的开关（默认关，俯视全景）。

## 4. 3D 美术与场景规范

### 4.1 渲染与相机

- `WebGLRenderer({ antialias:true, powerPreference:'high-performance' })`，`shadowMap.enabled = true`，`type = PCFSoftShadowMap`，`outputColorSpace = SRGBColorSpace`。
- `PerspectiveCamera(45, w/h, 0.1, 100)`，**斜俯视**机位（约 45°~55° 俯角），棋盘居中。
- 提供 `fitCamera()`：根据视口宽高比自动调整机位距离与 FOV 保证棋盘四角留白安全，横屏 / 竖屏 / 桌面均无裁切（竖屏手机应让棋盘竖放占满高度）。

### 4.2 光照

- `HemisphereLight`（天空暖白 / 地面木褐）+ `DirectionalLight`（主光，斜上方）投射阴影，`shadow.mapSize` 1024~2048，`shadow.camera` 紧贴棋盘范围。
- 可选一盏低强度补光消除死黑。
- 阴影只对「棋子 → 棋盘」与「棋盘/桌 → 地面」开放，其余物件 `castShadow` 关闭以省性能。

### 4.3 材质与程序化贴图（全部 Canvas 绘制）

| 物件 | 规范 |
|---|---|
| 棋盘面 | Canvas 绘制木纹（多道不等宽深浅条纹 + 噪点）+ 黑色格线 + 九宫斜线 + 炮/兵位十字标记 + **楚河汉界**四字；`MeshStandardMaterial`，`roughness ≈ 0.55`，`metalness = 0` |
| 棋盘框 | 深色木质外框，`ExtrudeGeometry` 带 `bevelEnabled` 小倒角，厚 0.2~0.4 单位 |
| 棋子 | **`LatheGeometry` 车削**出圆饼鼓形（顶面平 + 侧面微弧 + 底部收边），所有棋子共用同一剖面，仅贴图与颜色不同；顶面与侧面圆环各一张 Canvas 贴图（红：`#b3241c` 底 + 白描边 + 阴刻字；黑：`#1d1d1d` 底 + 白描边 + 阴刻字） |
| 文字 | 字体栈与项目一致；为立体感在 Canvas 中做「深色内阴影 + 高光边」模拟刻字 |
| 桌面 / 场景 | 木桌或绒布（Canvas 纹理，`repeat` 平铺），可选暗角渐变背景；**禁止外部 HDR / 环境贴图** |
| 单位尺度 | 以「一格 = 1 单位」为基准，棋子直径 ≈ 0.85 格，厚 ≈ 0.25 格 |

### 4.4 建模落地路径（重要工程决策）

优先 **A**，仅在确有美术需求时用 **B**：

- **A. 程序化几何（推荐，默认方案）**：用 `LatheGeometry` / `ExtrudeGeometry` / `CylinderGeometry` / `TorusGeometry` 在代码中直接构建棋子、棋盘、托盘、桌面。完全符合零依赖与体积约束，且可参数化调节。Blender 在此仅用作**造型参考与出图**。
- **B. Blender 建模 + 精简顶点数据内联**：在 Blender 中建模后，用脚本（`tools/blender_export.py`）导出为**纯 JSON 顶点 / 法线 / UV / 材质名数组**，内联进 `<script type="application/json" id="mesh-xxx">`，再用手写 `BufferGeometry` 装配。**禁止**内联 base64 的 `.glb`/`.gltf`（体积与解析器成本不可接受）。约束：
  - 全模型总顶点数 ≤ 3 万，内联 JSON ≤ 150 KB；
  - 必须同时提交 `.blend` 源文件与导出脚本到仓库（作为开发资产，不参与运行时）；
  - 若导出后总体积超 900 KB，回退方案 A。

### 4.5 视觉反馈（必须实现的 6 种）

1. **选中态**：棋子下方出现呼吸光晕环（柔光纹理 plane，`depthWrite:false`，`opacity = 0.75 + 0.25*sin(t)`）。
2. **可落点标记**：合法目标格显示半透明发光圆盘；吃子格用红调标记区分。
3. **上一步标记**：起止两格显示低调方框标记（不同颜色）。
4. **将军提示**：被将军方的将/帅材质叠加红色脉冲发光，顶部信息条显示「将军！」。
5. **落子动画**：棋子沿弧线 / 缓动平移 + 轻微下压回弹，时长 220~320 ms，`easeOutCubic`。
6. **吃子动画**：被吃棋子上浮、旋转、淡出（合并到棋盘侧边的"被吃区"），时长 ≈ 350 ms；此期间 `busy = true` 屏蔽输入。

## 5. 交互规范

### 5.1 拾取

- 使用 `THREE.Raycaster` 对「棋子」与「合法落点标记」做拾取；同时提供**平面格点回退**：射线与棋盘平面求交后换算为最近格点，用于点空白处落子和宽容点击。
- 触屏直径较小的棋子需有**命中容差**（例如以棋子中心为圆心、半径 ≥ 0.55 格的圆柱命中域）。
- 坐标系：`worldFromGrid(col,row)` / `gridFromWorld(x,z)` 双向换算函数必须集中定义，禁止散落魔法数字。

### 5.2 操作流程

1. 点击己方棋子 → 选中（光晕）+ 显示全部合法落点；再次点击同一子 → 取消。
2. 点击合法落点 → 执行走子（动画 + 音效）；点击非法位置 → 抖动 + `err` 音效 + 顶部提示原因（如「马腿被蹩」「不能送将」「将帅不能照面」）。
3. 未选中棋子时点击对方棋子 → 显示该子的可走范围（仅预览，不可确认）。

### 5.3 对局操作栏

- 按钮：`悔棋`、`认输`、`重开`、`提示`（高亮一步推荐着法）、`暂停`、`返回首页`。
- 悔棋规则：双人模式退 1 着；人机模式退 2 着（回到玩家回合）；无历史时按钮置灰。
- 所有操作均需二次确认弹窗（除暂停），参照项目的 `PauseModal` 写法。

### 5.4 动画与输入屏蔽

- 全局 `Busy` 计数器 / 标记：落子、吃子、AI 思考、结算动画期间屏蔽拾取分发。
- 复用「单一入口分发」模式：`dispatchTap(...)` 按当前屏幕路由，手柄导航与触摸**共用同一入口**。

## 7. AI 规范

### 7.1 难度分档

沿用参照物的 4 档命名与色标（`AI_LEVELS` 结构：`{name, desc, cls, hex}`）：

| 档位 | 策略 |
|---|---|
| 1 简单 | 浅层搜索（1~2 层）+ 随机噪声，允许明显失误，用于新手 |
| 2 普通 | 3 层 Alpha-Beta + 位置表评估 |
| 3 困难 | 5 层 Alpha-Beta + 走法排序 + 静态搜索（吃子扩展 2 层）+ 简单置换表 |
| 4 大师 | **迭代加深** + 时间预算（800~1500 ms）+ 置换表 + 杀手着法 + 空着裁剪（可选） |

### 7.2 搜索与评估（必须手写，禁止用库）

- 算法：`negamax` + `alphaBeta` + `quiescence`；节点数控制与超时中断（`Date.now()` 检查）。
- 评估函数：`子力价值 + 位置价值表(PST) + 机动性 + 将帅安全 + 兵卒过河奖励`。
  - 子力基准建议：车 900 / 马 400 / 炮 450 / 士 200 / 象 200 / 兵 100（过河后递增）/ 将 10000。
  - 位置价值表按棋子类型分别定义（可用 10×9 常量数组），鼓励车占要道、马贴边减分、兵过河加分、炮镇中路。
- 走法排序：吃子优先（MVV-LVA），其次杀手着法 / 历史启发。
- 从**根节点的合法着法**中选取最优；评分持平时加入微随机，避免 AI 每局完全相同的开局。

### 7.3 异步与体验

- AI 思考必须**非阻塞**：优先「分片搜索 + `setTimeout(0)` / `requestIdleCallback` 让帧」，或把搜索拆成多段按时间预算推进；**单次同步阻塞不得超过 ~120 ms**，否则低端设备会掉帧（参照物在 MCTS 上出现过同步阻塞问题，务必避免）。
- 思考期间：显示「AI 思考中…」+ 棋子/信息条轻微脉冲；`AI.running` 防重入；暂停或切屏时放弃本次思考。
- 延时：`260 + lv*220 + (1000~3000 随机)` ms 区间（参照物同款节奏），避免瞬间落子造成突兀。

## 8. 数据与持久化

- localStorage key 命名沿用参照物风格：
  - `cc_save_v1` —— 当前对局（最多 1 份）
  - `cc_records_v1` —— 历史对局（最新在前，上限 50）
  - `cc_zoom_v1` —— 缩放偏好（可选，50%~200%）
- 存档结构（示意，实现时按此定义并做版本字段）：
  ```js
  { v:1, mode:'ai'|'pvp', aiLevel:3, playerSide:'red'|'black',
    board:[/* 10×9，'rR'/'bM'/null 之类编码 */], side:'red',
    history:[{from:[c,r], to:[c,r], piece, captured, notation:'炮二平五'}],
    fens?/hash?, startedAt, elapsed }
  ```
- 读档必须**校验结构**（缺字段即视为坏档并静默丢弃），失败回退首页；读档成功后若轮到 AI 则自动接上。
- 记谱序列随存档保存，保证回放可用。

## 9. 性能与移动端适配

- DPR ≤ 2；`resize` / `orientationchange` 防抖 200 ms 后重建布局（横竖屏切换延迟 250 ms 等待系统旋转完成）。
- 纹理使用 `TEX` Map 缓存，key 带尺寸；场景重建时 `TEX.clear()`；局部失效按前缀删除；`disposeGroup` 必须逐个释放 geometry / material / map。
- 棋子贴图**按「阵营 + 字」缓存复用**，32 枚棋子不得各建一套重复纹理；同屏 mesh 数控制在 120 以内。
- 阴影贴图 1024（低端）~2048（桌面），可依据 `devicePixelRatio` / 视口尺寸降级。
- 目标：桌面 60 fps，中低端手机 ≥ 30 fps。
- UI 使用 DOM（HTML/CSS）叠在 canvas 之上，3D 只负责棋盘与棋子，避免在 canvas 里绘制大段文字 UI。

## 10. 代码组织规范

严格沿用参照物的分块与命名，脚本按以下顺序排列（每块顶部 `'use strict';`）：

1. `<style>`：加载页 / 弹窗 / 按钮 / 布局（按 `/* ===== xxx ===== */` 分段）
2. `<script>`：内联 three.js 压缩源码
3. `<script>`：**数据层** —— 棋盘尺寸常量、棋子定义、子力价值表、位置价值表(PST)、颜色、主题、难度档位 `AI_LEVELS`
4. `<script>`：**规则引擎** —— 棋盘/局面表示、走法生成、合法性判定、将军检测、终局判定、记谱生成、`newGame/execMove/undoMove`
5. `<script>`：**AI 层** —— `negamax` / `alphaBeta` / `quiescence` / `evaluate` / `decide` / `maybeRun` / `takeTurn`
6. `<script>`：**UI 层** —— `makeTex` / `text` / `mkTextMesh` / `addClickable` / `hitTest` / `setGlow` / `updateGlows` / 动画 `Tween` / `Busy`
7. `<script>`：**场景层** —— 模型构建（棋子 / 棋盘 / 桌面）、`Home` / `AISetupModal` / `GameScreen` / `EndScreen` / 各弹窗 / `showScreen` / 存档
8. `<script>`：**PadNav** —— 手柄 / 键盘方向导航（复用 `dispatchTap` 入口）
9. `<script>`：**主入口** —— `initApp` / `resize` / `rebuildScreen` / `dispatchTap` / `playSfx` / `animate`

约定：
- 全局状态用对象字面量 + 全局单例（`G` / `SceneRoot` / `Screen` / `UI` / `AI`），**不使用 ES module**。
- 常量全大写；函数名小驼峰；注释用中文，段落用 `/* ===== 标题 ===== */` 分隔。
- 规则引擎（数据层 + 规则层 + AI 层）**不得依赖 DOM 与 Three.js**，并把核心 API 挂到一个全局对象上（如 `window.CC_RULES = {...}`），便于用 Node 提取做单元测试。
- 纹理中所有坐标以「格」为单位换算，禁止散落魔法数字。

## 11. 音效规范（WebAudio 合成，零素材）

用 `AudioContext` + `OscillatorNode` / 噪声 `BufferSource` + `BiquadFilter` 现场合成，`unlockAudio()` 必须在用户手势中调用（iOS 需补播一帧近静音 buffer）。

必须实现的音效 key：

| key | 音色设计 |
|---|---|
| `pick` | 短促木鱼感单击（三角波 880 Hz，衰减 0.06 s），选中棋子 |
| `drop` | 木质落子「啪」：噪声瞬态 + 300~500 Hz 带通，衰减 0.12 s，落子 |
| `capture` | 落子音 + 低频撞击（120 Hz 正弦 + 噪声），吃子 |
| `check` | 上行紧张双音（G5 → C6 快速滑音），将军 |
| `err` | 200 Hz 方波短促，非法操作 |
| `nav` | 1245 Hz 三角波极短音，手柄 / 按钮导航 |
| `undo` | 反向滑音（向下），悔棋 |
| `win` / `lose` | C5-E5-G5-C6 琶音 / 下行琶音，结算 |
| `start` | 523 Hz，开局 |

支持 `volScale` 参数在密集场景临时降音量；提供静音开关并持久化到 `cc_zoom_v1` 同级的设置 key（如 `cc_settings_v1`）。
