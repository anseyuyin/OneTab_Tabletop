# 《荣光宝石商》 Glory & Gems

> 一款 2~4 人同设备轮流的宝石商人桌面游戏电子版。
> 单文件 HTML 实现，基于 Three.js 2D 场景，适配手机 / 平板 / 电脑浏览器。

---

## 一、项目概述

| 项目 | 说明 |
|---|---|
| 游戏名称 | 《荣光宝石商》（Glory & Gems） |
| 玩家人数 | 2 ~ 4 人，同一台设备轮流操作 |
| 游戏平台 | 浏览器（手机 / 平板 / 桌面），**双击 `index.html` 即玩，无需联网** |
| 开发平台 | Three.js（正交相机 2D 场景，全部 UI 为 Canvas 纹理平面网格） |
| 交付形态 | 单文件 `index.html`（约 660KB，three.js 已内嵌） |
| 界面语言 | 简体中文 |
| 核心玩法 | 收集宝石、购买发展卡（矿卡）、吸引贵族，率先达到 15 分并完成本轮者获胜 |

### 设计特点
- **单文件交付**：所有程序、数据、素材（纹理均为 Canvas 运行时绘制）内嵌于一个 HTML。
- **四边坐席**：玩家信息面板分别放置在屏幕的上 / 下 / 左 / 右四边，文字朝向各坐席玩家（下方正立、上方倒置、左右侧转）。
- **触屏交互**：全部操作通过「点击 + 文本提示 + 按钮执行」完成；可选目标边缘发光（绿 = 可选，蓝 = 已选中）。
- **自适应布局**：竖屏手机、横屏平板、桌面窗口均自动重排。

## 二、玩法规则

### 1. 宝石资源
- 五种宝石：**钻石（白）、蓝宝石（蓝）、祖母绿（绿）、红宝石（红）、黑曜石（黑）**，外加万能资源 **黄金**。
- 宝石是通用货币：购买发展卡时可用任意颜色的宝石组合支付；**黄金可当任意宝石**（不足时自动补差）。
- 玩家**每种宝石最多持有 10 个**（黄金不计入上限）；游戏内显示「宝石 X/50」（5 色 × 10）。

### 2. 发展卡（矿卡）
- 三个等级：
  - **1 级牌** 40 张：0~1 分（0 分 35 张 + 1 分 5 张），成本合计 3~5 宝石，提供 1 个对应色折扣
  - **2 级牌** 30 张：1~3 分（1 分 10 张 + 2 分 15 张 + 3 分 5 张），成本合计 5~8 宝石，提供 1 个对应色折扣
  - **3 级牌** 20 张：3~5 分（3 分 5 张 + 4 分 10 张 + 5 分 5 张），成本合计 7~14 宝石，提供 1 个对应色折扣
- 每级分为 4 叠牌堆，每叠顶部亮出 1 张（共 12 张展示牌）。
- 购买后该牌提供**永久折扣**：购买牌面标色宝石的需求 -1（按所持矿卡计数），并可累积得分。

### 3. 贵族卡
- 共 10 张标准贵族卡，每张 3 分，要求持有**指定组合的发展卡张数**（如 3 白 + 3 蓝 + 3 黑）。
- 当局使用 **玩家人数 + 1** 张（2 人 3 张 / 3 人 4 张 / 4 人 5 张），随机抽取。
- 回合结束时若满足条件则自动获得；同时满足多张时可**选择一张**获得。

### 4. 回合动作（每回合四选一）
| 动作 | 说明 | 条件 |
|---|---|---|
| **拿 3 色宝石** | 从宝石堆拿取 3 种不同颜色的宝石各 1 个 | 该色有货且持有 < 10 |
| **拿 2 个同色** | 从宝石堆拿取同色宝石 2 个 | 该色堆 ≥ 4 个且持有 +2 ≤ 10 |
| **购买发展卡** | 支付宝石购买 1 张展示牌（或自己保留的牌） | 持有宝石+黄金足够支付 |
| **保留 + 黄金** | 保留 1 张展示牌（牌堆顶亦可），同时获得 1 个黄金 | 黄金堆有货、保留 < 3 张 |

- 保留的牌仅本人可购，每人最多保留 3 张（「黄金压卡」）。
- 买牌后：扣除宝石（归还银行）、获得矿卡折扣与分数、展示位自动补牌。

### 5. 胜利条件
- 任一玩家回合结束时得分 ≥ **15 分**，触发终局；其余玩家完成本轮后游戏结束。
- 结算：总分最高者获胜；平分时**开发卡较少者**胜；仍平则并列获胜。

| 3 人 | 5 | 4 | 4 |
| 4 人 | 7 | 5 | 5 |

## 三、游戏流程

```
启动首页
   │ 选择人数（2 / 3 / 4）→ 开始
   ▼
开局（随机先手）
   ▼
┌── 回合循环 ────────────────────────────────┐
│ 当前玩家面板高亮（金色底部亮条 + 边框）         │
│   1. 点击下方动作按钮（拿3色 / 拿2个 / 购买 / 保留）│
│   2. 可选目标边缘发绿光，点击选中变蓝光         │
│   3. 阅读操作栏文本提示，点「执行 ✓」完成动作     │
│   4. 回合结算：买牌补位 → 贵族检查（多张则选择）  │
│   5. 得分 ≥ 15 触发终局提示，轮完一圈            │
│   6. 切换到下一位玩家                          │
└────────────────────────────────────────────┘
   ▼
终局结算：高亮展示获胜者（并列则多人高亮）
   ▼
「返回首页」按钮 → 回到首页重新开局
```

### 交互细则
- 所有可交互元素：**可选 = 绿色描边发光**，**已选中 = 蓝色描边发光**（含动作按钮、宝石堆、展示牌、保留牌、贵族卡）。
- 操作栏始终显示当前动作的文本说明；非法点击有提示音。
- 保留牌缩略卡显示在玩家面板上，点击弹出「保留牌」模态框，可选中并购买。

```
    ├── part5_screens.js  # 场景层：布局计算、首页/游戏/结算、面板、保留模态
    ├── part6_main.js     # 主入口：渲染器、相机、输入、音效、动画循环
    ├── three.min.js      # three.js r149（UMD，构建时内嵌）
    └── test.js 等        # 无头浏览器自动化测试与诊断脚本
```

### 技术要点
- **渲染**：`THREE.OrthographicCamera` + `PlaneGeometry` + `MeshBasicMaterial`，世界坐标以 CSS 像素为单位。
- **纹理**：所有 UI 由离屏 `Canvas` 绘制生成 `CanvasTexture`；面板等动态纹理不缓存（随回合重绘）。
- **交互**：`pointerdown/up` 事件 → 世界坐标换算 → AABB 命中测试（按 z 层级取最上层）。
- **四边朝向**：上下面板 mesh 旋转 0°/180°；左右面板纹理内旋转 +90°/-90°（内容横向排布立于屏幕左右缘）。
- **数据来源**：牌组为实体卡牌照片验证数据（anicolao/splendor verified_card_properties.csv），贵族卡为标准 10 张（与多个开源实现交叉核对）。注：游戏内 8 张牌的成本与源 CSV 存在差异（见更新日志 v1.5）。
- **音效**：WebAudio 振荡器合成（无外部资源）。
